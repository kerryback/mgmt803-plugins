How should I read the arrows?

Solid arrows represent goals, delegation, tool calls, requests, returned work, and the final result. Dashed arrows represent support relationships: the model powers the agent, context informs it, skills guide it, and a plugin can package skills and connections. The chart is a conceptual map rather than a strict execution sequence.

Can you give me a concrete example?

Suppose you ask for a summary of a spreadsheet. The main agent uses the model to interpret your request and your project instructions for context. A spreadsheet skill may tell it how to check the data. It calls a local file tool or a connected Sheets tool, may delegate a focused check to a subagent, then combines the findings into an answer. If it uses a connected Sheets tool, a connector may pass requests to an API that reaches the spreadsheet service.

What does this simplified map leave out?

Products differ in which skills, tools, plugins, and subagents they support. A subagent may have its own model, context, and skills. Access to files or external systems depends on the permissions and authentication available in that environment.
